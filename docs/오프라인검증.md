# 오프라인 검증과 answer_coverage

## 1. 무엇인가

| 항목 | 의미 |
| --- | --- |
| `run --offline` | RAG 없이 정답 문장을 답변으로, 정책 원문을 검색 결과로 넣어 채점. "정답을 그대로 냈을 때 몇 점이 나오는가"를 잰다 |
| `answer_coverage` | 답변이 정답의 사실을 빠짐없이 말했는지(정답 주장 중 답변에 있는 비율). 정답 밖 사실을 덧붙여도 감점하지 않는다 |

> offline은 채점의 "만점 기준"을 재는 실행이고, answer_coverage는 그 기준이 1에 가까워야 하는 우리 쪽 지표다.

## 2. 왜 필요한가

| 이유 | 내용 |
| --- | --- |
| RAGAS가 아니라 연결부 검증 | RAGAS 라이브러리는 검증할 필요가 없지만, 인자 매핑·채점 모델(Bedrock) 호환·임베딩 연결은 mock 단위 테스트로 못 잡는다 |
| 직접 만든 지표 확인 | `answer_coverage`는 RAGAS 기본 지표가 아니라 직접 구현했다. 정답을 넣었는데 1이 안 나오면 구현이나 분해 옵션 문제다 |
| 점수 상한 확인 | LLM 판정이라 정답을 넣어도 1이 안 나오는 지표가 있다. offline 점수를 알아야 RAG 점수(예: 0.85)가 높은지 낮은지 해석할 수 있다 |
| factual_correctness 보완 | `factual_correctness`는 정답 밖 사실을 감점해, 친절하게 더 설명한 RAG 답변이 낮게 나온다. 누락만 보는 `answer_coverage`를 함께 봐야 "정답을 빠뜨렸는지"를 따로 알 수 있다 |

> RAG 점수를 믿으려면 "정답이면 몇 점인가"를 먼저 알아야 한다. offline 1회로 그 기준과 직접 만든 지표의 정상 동작을 함께 확인한다.

## 3. 언제 돌리나

채점 모델·지표 코드·데이터셋 버전이 바뀔 때 1회. 매 평가마다 돌릴 필요는 없다.
